## 一、 极速上手：将 Gemini Pro 接入 VS Code

如果你还没有完成基础配置，只需简单的三个步骤：

1. **获取“钥匙”：** 访问 [Google AI Studio](https://aistudio.google.com/)，登录账号并免费申请一个 API Key。
2. **安装“基座”：** 在 VS Code 的扩展商店中搜索并安装开源插件 **Continue**。
3. **完成“连接”：** 点击 VS Code 侧边栏的 Continue 图标，点击底部的齿轮图标 (⚙️) 打开 `config.json`，将 Gemini 加入你的模型列表：

```json
models:
  - name: Gemini 3.1 Flash
    provider: gemini
    model: gemini-3.1-flash-preview
    apiKey: API Key
```
保存后，在聊天面板选择 Gemini 3.1 flash，你的 AI 助手就正式上线了！


## 二、 进阶玩法：为什么你需要配置 Rules 功能？

默认状态下的 AI 就像一个刚毕业的实习生，能力很强，但不懂你们公司的“规矩”。每次让他写代码，你可能都要重复唠叨：“记得用 TypeScript 写”、“别用 Class 组件”、“加上中文注释”……

**Continue 插件的 Rules（规则）功能，就是为了解决这个问题而诞生的。** 它相当于为你的 AI 设定了“系统级行为准则”或“人设”。配置好之后，AI 每次回答前都会默认读取这些上下文，做到真正的“懂你”。

根据不同的需求，你可以选择在以下三个层级配置规则：

### 1. 全局级：写在 Rules Global 里
适合你个人的通用习惯,全局行为约束 + 输出规范。无论打开什么项目，AI 都要遵守的底线。
```md
# Rules: Core Principles
- Only modify the selected files/functions; do not rewrite entire files.
- Simple formatting or renaming tasks should be executed directly without explanation.
- Prefer incremental changes in Git diff style.
- Avoid outputting unrelated code context.

# Response Format
**For simple changes** (formatting, renaming):
- Output only the modified code snippet.
- Do not include confirmation messages like "Understood."
- Do not explain why the change was made.

**For complex changes**:
- Briefly describe the modification in 1-2 sentences.
- Output only the changed code blocks.
- Use `// ...` to indicate unchanged parts.
```

### 2. 项目级（单文件）：`.continuerules`
如果你的规则针对特定项目（比如这是个 Vue3 项目，不能混入 React 的写法），只需在**项目根目录**新建一个 `.continuerules` 文件。这非常适合与团队代码库一起提交。

### 3. 项目级（文件夹）：`.continue/rules/`
对于大型企业级项目，规范繁杂。你可以在项目根目录建一个 `.continue/rules/` 文件夹，在里面分门别类地写 `style.md`、`testing.md` 等规则文件，Continue 会自动将它们全部读取。例如`style.md`：

```md
---
name: 风格要素
description: 写作风格
invokable: true
---

## Long-Term Writing Context 

1. 中长文本必须存在一个隐喻或历史意象作为逻辑骨架。
2. 隐喻必须可映射为现实中的工程、组织或制度问题。
3. 所有抽象判断必须拆解为：条件 / 能力 / 行动 / 边界。
4. 每篇文章至少包含一次结构性反问，用于强化判断。
5. 长短句交替，关键判断独立成段。
6. 不允许停留在观察或评论层面，必须导向行动。
7. 必须显式或隐式说明责任归属与失效条件。
8. 禁止宏大叙事替代微观落地路径。
9. 所有价值判断必须对应可执行结构。
10. 结尾需回归“行动或结构延续”，而非情绪收束。
11. 禁止使用以下类似词汇：难道 / 不仅 / 更是 / 而是 。
```

## 四、 总结：Rules 带来的三大改变

收束边界： 彻底切断大模型的“无效热情”与“宏大叙事”。通过严格的输出约束，将 AI 从一个啰嗦的聊天对象，重塑为只提供精准 Diff 和核心逻辑的执行机器。

隐性经验显性化： 告别每次对话前繁琐的背景铺垫。将个人的代码洁癖、团队的工程规范，甚至抽象的写作思维骨架，全部固化为可复用的数字资产，让 AI 具备真正的“上下文记忆”。

从观察者到构建者： Rules 强迫大模型跨越“解释与评论”的表层。无论是修改一行代码，还是构建一篇长文，都在既定的逻辑约束下发生，确保每一次输出都具备清晰的可执行结构与现实映射。
